# Plan — 프로토타입 → 실제품 수준 업그레이드

## 변경 목적

정적 목업 수준이던 데스크톱 프로토타입을 "실제 프로젝트처럼 쓸 수 있는" 상태로
끌어올린다. 저장·확정·발송·분류가 실제로 상태를 바꾸고, 화면 간 데이터가
일관되게 흐르며, 디자인(스페이싱·타이포·모션)이 제품 수준으로 정돈되어야 한다.

## 변경 범위

1. **데이터 모델** — `lib/types` 전면 확장 (아동 프로필, 하루 기록, 문서
   상태머신, 사진 분류 상태, 관찰 태깅, 상담 세션, 규칙엔진 체크리스트)
2. **목 백엔드** — 정적 JSON 반환 → 상태형 인메모리 DB(`mocks/db.ts`) 위에서
   동작하는 MSW 핸들러. 알림장 초안은 하루 기록에서 파생 생성.
3. **디자인 시스템** — `globals.css` 정돈: 4px 스페이싱 그리드, 트랜지션 토큰,
   모달·아바타·세그먼트·레일 등 신규 부품, hover/press 인터랙션.
4. **화면 전환·모션** — `template.tsx` 페이드업 전환, framer-motion 기반
   ConfirmDialog/Modal, 사진 그리드 layout 애니메이션.
5. **12개 화면 재작성** — 전부 실데이터 흐름으로 연결.

## 접근 방식

- 서버 상태의 단일 원천은 TanStack Query, 문서 상태는 서버(DocumentDraft.status)가 소유.
- `window.confirm` 제거 → 디자인된 ConfirmDialog.
- 명세 주석(SpecBar·번호 배지)은 유지하되 기본 off (상단바 토글).
- 백엔드 연결 시 `mocks/` 제거 + `NEXT_PUBLIC_USE_MOCK=false`만으로 전환 가능하게 계층 유지.

## 검증 계획

- `npm run type-check` · `npm run lint` · `npm run build` 통과
- 정적 export(`out/`) 서빙 후 13개 라우트 200 확인
- 핵심 플로우 수동 시나리오: 기록 저장 → 알림장 초안 파생 → 수정(자동 저장) →
  확정(편집거리) → 발송 → 체크리스트·대시보드 반영 → 시드 초기화
